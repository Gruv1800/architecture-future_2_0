# Проблемные места и их приоритезация с использованием подхода MoSCoW

| Приоритет   | Наименование проблемы                                                                                                       | Решение                                                                                                                                                    |
|-------------|-----------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Must Have   | Долгое время генерации отчетов и поиска нужных данных, связанное с низкой производительностью системы в целом               | Переход на современный стек технологий: Apache Camel -> Kafka, Ms SQL Server -> DataLakeHouse + хранение данных в доменах (Postgres)                       |
| Must Have   | Низкий уровень Time-To-Market из-за монолитной архитектуры системы                                                          | Выделение доменов, разбиение системы на микросервисы по DDD подходу                                                                                        |
| Must Have   | Возможность утечки и\или порчи данных из-за отсутствия ролевой модели доступа к данным                                      | Интеграция RBAC\ABAC модели доступа к данным                                                                                                               |
| Should Have | Сложный порог входа для новых сотрудников системы                                                                           | Реализация нового интерфейса "Витрины данных"                                                                                                              |
| Should Have | Возможные финансовые и репутационные риски из-за несоответствия подходов хранения и передачи конфиденциальных данных 152 ФЗ | Передавать данные с использование защищенных протоколов (SSL\TLS) +  шифровать конфиденциальные данные на уровне БД                                        |
| Could Have  | Периодически возникает путаница с источниками данных, что привносит сложности в их анализ                                   | Внедрение инструментов визуализации потоков данных - Data Linage                                                                                           |
| Could Have  | Наличие дополнительных расходов на лицензирование проприетарных BI инструментов                                             | Перейти на самописные решения с использованием OpenSource инструментов                                                                                     |
| Won't Have  | Полный отказ от устаревшего DWH                                                                                             | Остановка всей бизнес-логики DWH и связанной инфраструктуры, когда текущие процессы будут полностью работать на новом стеке и DataLakeHouse инфраструктуре |
